# WebMic —— 把手机变成电脑的麦克风

手机采集声音，通过局域网低延迟传给电脑，电脑把它输出到一个虚拟声卡，
于是微信 / Zoom / OBS / 音乐软件就能在“麦克风”列表里选到它。

主要面向**唱歌、乐器、语音输入**：全程传裸 PCM，不走 Opus 转码，
默认 40ms 抖动缓冲，可低到 20ms。

```
手机(HTTPS 页面)                    电脑(Node)                   电脑
麦克风 → AudioWorklet → PCM ──WS──▶ 中继 ──WS──▶ 接收页 → CABLE Input
                                                              ↓
                                              软件里选 CABLE Output 当麦克风
```

---

## 一、快速开始

```powershell
npm install
npm start
```

启动后终端会显示：

```
本机接收页:      http://localhost:8080
其他电脑接收页:  https://192.168.x.x:8080
手机发送页:      https://192.168.x.x:8080/mic
```

> **8080 端口同时支持 http 和 https**：本机用 `http://localhost:8080` 打开不用折腾证书；
> 第二台电脑 / 电视必须用 `https://<电脑IP>:8080`（浏览器只在安全上下文里允许 AudioWorklet
> 和设备选择），首次打开点“高级 → 继续前往”即可，也可以在 B 机上打开
> `https://<电脑IP>:8080/cert` 下载证书并导入“受信任的根证书颁发机构”。

> 需要 Node.js 16.17 或更高版本。

## 二、让电脑“长出”一个麦克风（只需配一次）

1. 下载安装 [VB-Audio Virtual Cable](https://vb-audio.com/Cable/)（免费），安装后重启电脑。
   系统播放设备里会多出 `CABLE Input`，录音设备里会多出 `CABLE Output`。
2. 打开 `http://localhost:8080`，在“播放到哪个设备”里选 **`CABLE Input (VB-Audio Virtual Cable)`**。
   如果下拉框里只有“系统默认输出”，点旁边的 **“选择…”** 直接挑选（不需要麦克风权限），
   或者点“刷新”并允许一次麦克风权限——只用于读取设备名，不会录音。
3. 点圆形按钮开始接收。
4. 在微信 / OBS / 音乐软件里，把麦克风（输入设备）选成 **`CABLE Output`**。

之后每次只要：启动服务 → 打开接收页点开始 → 手机点开始。

> 不想装驱动？Windows 的“立体声混音”也能用，但它会把电脑正在播放的声音一起录进去，
> 唱歌时基本不可用，所以默认推荐 VB-Cable。详见下一节的零安装方案。

## 三、不想装驱动？零安装的三种用法

接收页会自动检测电脑上有没有「虚拟声卡」和「立体声混音」，并在卡片里直接给出建议。
不装任何第三方软件也能覆盖下面三类场景：

### 1. 会议 / 网课 / 语音聊天 —— 系统自带的「立体声混音」

1. 接收页“播放到哪个设备”保持 **系统默认输出**（声音照常从音箱/耳机出来）。
2. 在微信 / Zoom / Teams / 腾讯会议里，把麦克风选成 **`立体声混音`**
   （有的驱动叫 `Stereo Mix` / `What U Hear` / `Wave Out Mix`）。
3. 如果录音设备列表里没有它：右键任务栏音量 → 声音设置 → 更多声音设置 →
   “录制”标签页 → 右键空白处 → 勾选“显示禁用的设备”，再启用“立体声混音”。

> 缺点：它会把电脑正在播放的所有声音一起送出去，对方会听到你的伴奏/视频声。
> 想避免听到自己说话，把会议软件的声音输出到另一块声卡（USB 耳机、HDMI 显示器），
> 或者在会议软件里开启回声消除。

### 2. 直播 / OBS —— 应用程序音频采集

不用虚拟声卡，也不会占用真实麦克风：

- 在 OBS 里添加 **「应用程序音频采集」**（Windows 10 2004+ / OBS 28+），
  目标选运行接收页的浏览器（Chrome / Edge），就只会把这路手机声音送进直播。
- 或者添加 **「浏览器源」** 打开接收页，并勾选“控制音频”。

这样手机人声可以和真实麦克风、游戏声音分别调音量。

### 3. 只想录一段人声 —— 内置 WAV 录制

接收页点 **“● 录制为 WAV”**，停止时自动下载 16bit / 48kHz 单声道 WAV：

- 录的是手机发来的原始 PCM，不经过播放缓冲，**断流/爆音不会进文件**。
- 最长 20 分钟（约 115MB），到上限会自动保存。
- 拖进 Audacity / PR / 剪映等任何软件继续处理。

### 唱歌 / 乐器 / 必须“只把手机当麦克风”

这一类仍然需要虚拟声卡。Windows 没有内置的虚拟录音设备，立体声混音会把伴奏一起录进去，
蓝牙免提（HFP）又只有 16kHz 且延迟很高。装一次 **VB-Audio Virtual Cable** 是最省事的方案，
配置方法见上一节。

## 四、手机端连接

1. 电脑接收页上会显示房间号和二维码，用手机相机/浏览器扫它。
2. 首次打开会提示“连接不是私密连接”：
   - **Android Chrome**：点“高级” → “继续前往”，即可授权麦克风。
   - **iPhone Safari**：先点“显示详细信息” → “访问此网站”；
     然后打开页面里“高级设置”中的**下载证书**链接，到
     `设置 → 通用 → VPN 与设备管理` 安装描述文件，再到
     `设置 → 通用 → 关于本机 → 证书信任设置` 打开完全信任。
3. 回到发送页，确认房间号一致，点麦克风按钮。电脑接收页状态变成“手机已连接”即成功。

> 手机必须用 **https://** 地址访问，浏览器才允许使用麦克风。这是浏览器安全策略，无法绕过。

## 五、唱歌/乐器使用建议

- **戴耳机**。手机外放 → 麦克风 → 电脑 → 音箱 → 再进麦克风，会形成啸叫。
- 缓冲深度（接收页滑块）：网络好就调到 **30–40ms**；出现断流/爆音再往上加。
- 手机端已关闭降噪、回声消除、自动增益，保留原始音色。
- 想换用外接麦克风：手机发送页「高级设置 → 使用的麦克风」里选。
- 接收页的「断流次数」持续增长说明网络抖动大或手机性能吃紧，适当加大缓冲。
- 只想留一份干声：接收页“录制为 WAV”，不会被播放缓冲和断流影响。

## 六、常见问题

| 现象 | 原因与处理 |
|---|---|
| 手机提示无法使用麦克风 | 用了 http 地址。改用 `https://IP:8080/mic`（旧地址 `:8443` 仍可用）；iPhone 还要完成证书信任 |
| 第二台电脑当接收端报“无法启动音频输出” | 用 `http://IP:8080` 打开了。换成 `https://IP:8080`，首次点“高级 → 继续前往” |
| 电脑上听不到声音 | 接收页“播放到哪个设备”没选 `CABLE Input`；或软件里选错了输入设备 |
| 下拉框里没有 `CABLE Input` | 浏览器授权前不暴露设备名。点“选择…”（Chrome/Edge 120+，无需麦克风权限），或点“刷新”允许一次麦克风；都没有的旧浏览器可临时到 `chrome://settings/content/microphone` 授权 |
| 接收页诊断显示“未授权识别” | 点“刷新”并允许一次麦克风权限即可读出设备名；没有麦克风的台式机可直接点“选择…” |
| 声音断续/爆音 | 加大缓冲；检查 Wi-Fi 信号；关闭手机省电模式 |
| 有明显的“桶音”/回声 | 忘了关降噪（本程序已关）；或者你正在用“立体声混音”而不是 VB-Cable |
| 延迟很大（>200ms） | 蓝牙耳机/音箱会额外增加 100–300ms；唱歌请用有线耳机 |
| 页面刷新后设备列表是空的 | 点一下“刷新”；部分浏览器需要先有一次用户操作才返回设备名 |
| 换网络后手机打不开 | 电脑 IP 变了。重启服务会自动重签证书，重新扫码即可 |
| 端口被占用 | `node server.js --http-port 8090 --https-port 8443` |

## 七、工作原理

- **采集**：手机端 `AudioWorklet` 每 128 帧回调一次，降混单声道、线性插值重采样到 48kHz，
  转成 Int16LE，每 10ms 打包一帧（960 字节）发出去。不使用 `MediaRecorder`，
  因为 webm/opus 分片解码会引入 100ms 以上的额外延迟。
- **中继**：Node 服务端只按房间号转发，不做解码、不缓存，接收端跟不上就丢帧。
- **播放**：接收页的 `AudioWorklet` 维护 2 秒环形缓冲，按目标水位（默认 40ms）预调度播放；
  积压超过目标 +500ms 时丢弃多余样本并做 64 样本交叉淡化，避免爆音。
- **出声**：优先用 `AudioContext.setSinkId()` 直接把音频输出到 `CABLE Input`；
  不支持时降级为 `MediaStreamDestination → <audio>.setSinkId()`。
- **录制**：接收页在转发 PCM 给 Worklet 前复制一份原始帧，停止时按 16bit/48kHz
  单声道封装成 WAV 直接下载，不经过播放缓冲，因此不会受断流影响。
- **证书**：首次启动生成含本机所有内网 IP 的自签名证书（`certs/`），
  IP 变化时自动重签，否则手机会因证书不匹配而拒绝开放麦克风。

## 八、目录结构

```
server.js               HTTP/HTTPS 服务、WebSocket 中继、房间管理、二维码
lib/dual.js             同一端口 http/https 分流（8080 双协议）
lib/certs.js            自签名证书生成与自动重签
lib/static.js           静态文件服务
lib/dsp.js              重采样 / Int16 转换 / 环形缓冲 / WAV 封装（浏览器与 Node 共用）
public/receiver.html    电脑/电视接收页
public/sender.html      手机发送页
public/capture-worklet.js  采集侧 AudioWorklet
public/player-worklet.js   播放侧 AudioWorklet（抖动缓冲）
test/                   node --test 单元测试 + 服务端集成测试
docs/                   设计说明
legacy/                 最早的半成品页面（保留备查）
```

## 十、已知限制

- 只支持**同一局域网**。跨网需要自己搭 frp / cloudflared 之类的内网穿透。
- 同一房间同时只允许一台手机推流（后加入的会顶掉前一个）。
- 接收页需要保持在前台；建议用 Chrome / Edge（Firefox 不支持输出设备切换）。
